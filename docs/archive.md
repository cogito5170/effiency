# 컨텍스트 보관소 — 오래된 대화를 세션 밖으로

`relay/archive.py` · `relay archive` · `relay recall` · hook(`prompt` · `precompact` · `session`)

## 왜

긴 세션은 두 번 값을 치른다.

1. **토큰** — 요청마다 컨텍스트 전체를 다시 읽는다 (`docs/architecture.md` 의 N² 항).
2. **context biasing** — 앞에서 모델이 한 추측이 뒤의 답을 끌고 간다. 대화를 통째로 붙여 두거나
   모델의 예전 답까지 키워드로 찾아 넣으면 같은 병이 된다.

그래서 컨텍스트가 커지면 대화를 세션 밖 파일로 옮기고, 새 세션에는 **포인터 한 줄**만 넣는다.
비슷한 것을 다시 물을 때만 **한 줄 요약**을 붙이고, 원문은 필요한 줄만 꺼낸다.

## 구조 — se_new `graph/` 의 깃발 색인을 따른다

```
.relay/archive/chunks/<해시>.md   원문 그대로. 지우지도 줄이지도 않는다
.relay/archive/index.jsonl        찾는 길: {id, kind, status, flags, summary, chunk, hash, tokens, session, turn}
```

- **압축 '색인'이지 압축 '보관'이 아니다.** 원문을 줄여 보관하면 버린 것을 아무도 못 되찾는다
  (se_new `graph/README.md`). 줄이는 것은 모델에 들어가는 양뿐이다.
- 같은 원문(해시)은 다시 적지 않는다 — 같은 transcript 를 여러 번 보관해도 색인이 안 부푼다.
- 원문 해시가 색인과 다르면 `open` 이 경고한다 — 낡은 색인이 원문 행세를 하지 않게.
- `.relay/` 아래라 git 에 안 들어간다 (대화 원문이므로 올리지 않는다).

## 언제 무엇이 일어나나

| 때 | 하는 일 | 모델에 들어가는 것 |
|---|---|---|
| 프롬프트마다, 컨텍스트 ≥ `archive.trigger_context`(60k) | transcript 를 보관 | 없음 (한도 차단 메시지에 "보관했다" 한 줄) |
| Claude Code 자동 압축 직전 (`PreCompact`) | 크기와 상관없이 보관 | 없음 |
| `/clear` · 압축 뒤 새 세션 (`SessionStart`) | — | 포인터 한 줄 (~70 tok) |
| 새 프롬프트가 보관 기록과 겹칠 때 | 색인만 훑어 조회 | 한 줄 요약 최대 3개, 400 tok 이하 |
| 겹치지 않을 때 | — | **0** |
| `relay recall --open ID --query 낱말` | 원문에서 낱말 주변 줄만 | 발췌, 800 tok 이하 |

**폴더를 훑는 토큰을 줄이는 장치**: 조회는 `index.jsonl` 만 코드로 읽는다 (모델 토큰 0). 모델은
`ls` · `cat` 으로 폴더를 열지 않고 `relay recall` 의 한 줄 요약에서 id 를 골라 그 기록의 필요한 줄만 받는다.
지금 세션의 기록은 이미 컨텍스트에 있으므로 다시 붙이지 않는다.

## 기록의 종류 — gentleMonster `memory.py` 와 같은 어휘

| kind | 어디서 | transcript 에서 |
|---|---|---|
| `user_stated` | 사용자가 한 말 | 사용자 턴 |
| `source_fact` | 코드가 읽거나 잰 것 | 도구 출력 (Read · Bash · Grep …) |
| `model_inference` | 모델이 쓴 것 | 답변 · 모델이 쓴 파일 내용 |
| `summary` | 다른 기록의 요약. 사실이 아니며 `sources` 를 가진다 | 세션 요약 |

`status`: `active` · `superseded` · `retracted`. 믿음(`TRUST`)은 어디서 왔는가로만 정한다:
사용자·도구출력 3, 요약 1, 추론 0.

규칙 (`tests/test_archive.py` 가 하나씩 붙든다)

- **아무것도 지우지 않는다.** 상태 변경은 같은 id 의 새 줄이고 조회는 id 별 마지막 줄을 본다.
- **추론은 사실로 올라가지 않는다.** 조회 줄에 `추론·미검증` 이 붙고 같은 점수면 사용자 말·도구 출력이 앞선다.
  `supersede` 는 사용자 말이나 도구 출력으로만 된다. **세션 요약에는 모델의 말을 넣지 않는다.**
- **정정이 우선한다.** 정정 표현(`말고` · `아니라` · `instead of` …)이 든 사용자 말은 깃발이 2개 이상 겹치는
  예전 기록에 `conflicts_with` 로 이어지고, 조회 때 먼저 나오며 예전 기록에는 `이후 정정 있음` 이 붙는다.
  범위가 불분명한 정정으로 자동으로 덮지는 않는다 — 덮는 것은 `relay recall --supersede OLD NEW` 로만.

## 측정 (`python3 -m unittest tests.test_archive -v`, 합성 transcript 20턴)

```
[압축] 보관 전 컨텍스트 ~52259 tok → /clear 후 포인터 ~72 tok (0.14%)
[조회] 폴더 전체 읽기 ~51731 tok (29개 파일) → 색인 요약 ~194 tok + 원문 발췌 ~93 tok = ~287 tok (0.55%)
[부분 읽기] 원문 전체 ~2551 tok → 발췌 ~197 tok
```

토큰은 `relay/tokens.py` 의 근사치다. 합성 transcript 는 도구 출력이 크고 주제가 갈리게 만든 것이라
실제 세션의 비율은 다를 수 있다.

## 한계

- 깃발은 코드가 뽑는다 (잦은 낱말 · 파일 이름 · 그 턴의 질문 낱말). 동의어나 다른 언어로 물으면 못 찾을 수 있다
  — 한국어로 묻고 코드는 영어인 경우를 위해 도구 출력에 그 턴의 질문 낱말을 깃발로 함께 단다.
- 정정 감지는 표현 규칙이다. 표현 없이 바꾼 결정은 `--supersede` 로 표시해야 한다.
- hook 은 대화를 컨텍스트에서 지우지 못한다. 줄어드는 것은 `/clear` · 자동 압축 **이후**의 컨텍스트다.
